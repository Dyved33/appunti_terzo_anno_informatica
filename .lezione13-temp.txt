Express.js
• È un framework web per Node.js
• Progettato per creare applicazioni web e API
• Consente di aggiungere funzionalità (logging, autenticazione,
  …) tramite middleware

• Supporta un sistema di routing per gestire le richieste HTTP in
  base a vari percorsi e metodi (GET, POST, PUT, DELETE, .…)

• Integrabile con vari motori di template (Pug, EJS, …) per
  generare pagine HTML dinamiche

Application Programming
Interface (API)
• Insieme protocolli che permettono a diverse applicazioni di comunicare tra loro
• Tipi di API: di Sistema, di Libreria, Web
• API Web: permettono la comunicazione tra server e client, ad es. tramite HTTP
• Componenti di un'API Web:
   • Endpoint (URL ai quali le richieste possono essere inviate)
   • Metodi HTTP (GET, POST, PUT, DELETE)
   • Headers (informazioni aggiuntive inviate con una richiesta o una risposta HTTP)
   • Body (contenuto della richiesta o risposta, solitamente in formato JSON o XML)

REpresentational State
Transfer (REST)
• Stateless: ogni richiesta deve contenere tutte le informazioni
  necessarie, senza che il server mantenga lo stato tra le richieste

• Client-Server: il client gestisce l’interfaccia utente, mentre il server si
  occupa dell’archiviazione e della logica di business

• Cacheable: le risposte possono essere memorizzate nella cache per
  ridurre le chiamate al server e migliorare le prestazioni

• Uniform Interface: le API RESTful usano metodi HTTP standard (GET,
  POST, PUT, DELETE) per operare sulle risorse in modo uniforme

• Layered System: l’architettura può avere più livelli (proxy, bilanciatori
  di carico) senza che il client ne sia consapevole

Metodi HTTP principali
• GET:
  • Utilizzato per leggere o recuperare dati, es. ottenere un elenco di prodotti
  • I dati vengono passati in chiaro nell’URL
  • È idempotente (chiamate ripetute restituiscono lo stesso risultato)
• POST:
  • Utilizzato per inviare dati e creare nuove risorse, es. creare un nuovo
    prodotto

  • I dati vengono inviati nel corpo della richiesta HTTP (non visibili direttamente)
  • Non è idempotente (chiamate ripetute possono causare e etti collaterali)

Middleware in Express.js
• È una funzione che intercetta e gestisce le richieste HTTP prima
  che raggiungano la loro destinazione nale

• Può eseguire operazioni come l'autenticazione, la gestione degli
  errori, il logging, ecc.

• Un middleware ha accesso a:
  • req: l’oggetto richiesta
  • res: l’oggetto risposta
  • next: funzione che passa il controllo al middleware successivo

Tipi di Middleware

• Built-in Middleware (già inclusi in Express.js)
  • express.static(): per servire le statici
  • express.json() : per elaborare richieste con corpo JSON
  • express.urlencoded(): per elaborare dati nei form
• Custom Middleware (scritti manualmente)
• Third-Party Middleware (moduli esterni)

Esercizio 2 (cont.)
• Aggiungere un middleware che, ad ogni richiesta ricevuta dal server,
  stampa il metodo HTTP, l'URL della richiesta e la durata dell’operazione

  // Middleware per loggare il metodo HTTP, l'URL e la durata della richiesta
  app.use((req, res, next) => {
      const start = Date.now(); // Tempo di inizio
      res.on('finish', () => { // Eseguito quando la risposta viene inviata
          const duration = Date.now() - start;
          console.log(`${req.method} ${req.url} - ${duration}ms`);
      });
      next();
  });




• Questo middleware deve essere dichiarato prima delle altre route,
  altrimenti non verrebbe eseguito per le richieste già gestite

• Altri middleware (ad esempio quello per gli errori 404) devono essere
  dichiarati dopo le route per gestire ciò che non è stato intercettato prima

Cookie-parser
• È un middleware per Express.js che permette di leggere e
  gestire i cookie nelle richieste HTTP

• Il cookie viene impostato con il metodo res.cookie(name,
  value, options)

• Cookie-parser popola l’oggetto req.cookies per consentirne
  l’utilizzo (solo req.cookies richiede cookie-parser)

• È un modulo npm e va installato
  npm install cookie-parser

Esercizio 4

• Creare un server Express.js che gestisca i cookie utilizzando il
  middleware cookie-parser. Il server dovrà avere tre route:

  • /set-cookie: imposta un cookie
  • /get-cookie: legge il cookie
  • /clear-cookie: cancella il cookie
• Il cookie deve avere un tempo di scadenza (maxAge) e deve
  essere accessibile solo tramite HTTP (httpOnly)


                        Programmazione Web e Mobile con Laboratorio   23
const express = require('express');
const cookieParser = require('cookie-parser');

const app = express();
const PORT = 3000;

app.use(cookieParser());

// Imposta un cookie
app.get('/set-cookie', (req, res) => {
    res.cookie('username', 'Alice', { maxAge: 900000, httpOnly: true });
    res.send('Cookie impostato!');
});

// Legge i cookie
app.get('/get-cookie', (req, res) => {
    res.send(`Cookie ricevuti: ${JSON.stringify(req.cookies)}`);
});

// Cancella un cookie
app.get('/clear-cookie', (req, res) => {
    res.clearCookie('username');
    res.send('Cookie cancellato!');
});

app.listen(PORT, () => {
    console.log(`Server in ascolto su http://localhost:${PORT}`);
});
• L'opzione maxAge de nisce per quanto tempo un cookie sarà
  valido in millisecondi prima di essere automaticamente
  eliminato dal browser

  • In alternativa, è possibile usare l’opzione expires, che
     imposta invece una data di scadenza precisa

• L'opzione httpOnly: true rende il cookie accessibile solo
  tramite il server e non modi cabile da JavaScript lato client

  • Previene attacchi XSS (Cross-Site Scripting), dato che gli
     script malevoli non possono leggere il cookie

• L'operazione JSON.stringify(req.cookies) serve per
  convertire i cookie ricevuti in una stringa JSON più leggibile
